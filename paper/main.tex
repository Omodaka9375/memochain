\begin{abstract}
Long-horizon LLM agents carry memory either as an ever-growing prompt
($O(n)$ tokens per query) or as a vector store ($O(n)$ index, no synthesis).
We present \method{}, a neural memory that is \emph{constant-size},
\emph{streaming}, and \emph{cryptographically verifiable}. The entire
history of a document collection or chat session folds into a fixed
\statebytes-byte state (11 heads $\times$ 32 keys $\times$ 32 values, Q14
fixed-point int16) updated by a Delta rule in $O(1)$ per document. Because
the fold is pure integer arithmetic, the same inputs produce
bit-identical state digests in Python, native Rust, and a zkVM, which
lets us attach Mina-style recursive zero-knowledge proofs: a third party
verifies in ${\sim}28$\,ms that a 22\,KB memory capsule was honestly
computed from a committed input sequence under a committed writer,
without re-reading the history and without seeing the raw inputs. We
train the memory without any teacher model: gradients from a frozen
causal LM's cross-entropy loss flow through differentiable
memory-token injection, a reader head, and a straight-through Q14
quantizer into the Delta-rule writer. On held-out PersonaMem-style QA
(4{,}237 questions, 30 unseen users, 200 documents each), the
self-trained 22\,KB capsule lifts a frozen Qwen3-8B decoder from 58.18\%
to 64.69\% (hard questions 30.84\% to 38.16\%), matching a 388\,MB
cross-attention memory teacher (64.76\% / 38.16\%) whose KV cache
occupies 4.10\,MB---at $181.8\times$ smaller memory and with zero
teacher dependence in training. A capacity ablation shows the memory
gain saturates at a 10\,KiB state on gist-style QA: growing the state
$8.8\times$ moves the gain by only $+0.007$ nats. Training the same
22\,KB capsule on a real developer's 241 coding sessions doubles
coding-session recall ($+0.94 \to +1.76$ nats) while retaining 96.6\%
of the personal-QA gain. We release the full stack: an
OpenAI-compatible memory proxy in daily use, bit-exact Rust and SP1
zkVM implementations, and an honesty audit including negative results.
\end{abstract}

\section{Introduction}
An agent that reads, codes, or converses for months cannot keep its
history in the prompt. The two standard escapes both leak cost and
trust:

\begin{itemize}
\item \textbf{Full context} re-sends and re-attends over history every
turn. Cost grows without bound; latency and price follow.
\item \textbf{Retrieval (RAG)}~\cite{lewis2020rag} stores chunks in an
index and recalls top-$k$. Recall is lexical-adjacent, synthesis across
chunks is left to the decoder, and the index itself grows forever.
\end{itemize}

Latent-memory systems such as
Memorilla~\cite{memorilla2026} compress a collection into a fixed set of
memory tokens read by the decoder in $O(1)$, but the memory module
re-attends over all documents when writing ($O(n)$ per collection), the
resulting KV cache is megabytes, and nothing about the memory is
portable or verifiable: it exists only inside one model's attention.

\method{} asks a different question: \emph{what is the smallest memory
artifact that (a) absorbs an unbounded stream in $O(1)$ per write,
(b) is portable across processes and machines as a single file, and
(c) carries a proof that it was written honestly?} The blockchain
analogy is direct:
\begin{center}
\texttt{Mina:~~~~~new\_chain = fold(old\_chain, block) + recursive zk proof}\\
\texttt{\method{}:~~~~new\_state = fold(old\_state, doc)~~~+ receipt / zk proof}
\end{center}
Mina~\cite{mina2020} keeps a whole blockchain constant-size by
recursively proving each block transition against the previous proof.
\method{} keeps a whole conversation history constant-size by folding
each document into a fixed 22\,KB associative state and proving each
transition with a receipt chain that upgrades to a recursive succinct
proof~\cite{sp1}. The analogy is load-bearing: it dictated the
integer-only arithmetic (\S\ref{sec:state}), the receipt/accumulator
design (\S\ref{sec:receipts}), and the 22\,KB size target.

\paragraph{Contributions.}
\begin{enumerate}
\item A constant-size, $O(1)$-update neural memory with bit-exact
integer semantics (\S\ref{sec:state}): the Delta-rule
fold~\cite{schlag2021fast,yang2024delta} runs identically in Python, Rust, and a
zkVM; every write produces a SHA-256 receipt; state tampering is
detectable.
\item Mina-style recursive IVC over neural memory
(\S\ref{sec:zk}): a compressed STARK proves a 200-document fold
(238.9M cycles, 1.24\,MiB) and each $+1$-document recursive step
(33.8M cycles); verification is ${\sim}28$\,ms; the capsule extracted
from the proof's public values is byte-identical to the Python fold.
\item Distillation-free training (\S\ref{sec:training}): writer and
reader train end-to-end through a frozen LM's loss with
straight-through Q14 quantization. The trained capsule matches the
Memorilla teacher's held-out accuracy exactly (\S\ref{sec:eval}).
\item A capacity scaling law for quantized fast-weight memory
(\S\ref{sec:capacity}): the knee is at 10\,KiB; the 22\,KiB Mina-sized
state is past the knee; the binding constraints are the read/write
projections and the decoder's token budget, not state size.
\item Domain transfer from a real user's coding history
(\S\ref{sec:coding}): causal-prefix training on 241 real sessions
doubles coding recall while a joint multi-domain model keeps 96.6\% of
the original domain's gain.
\item An honesty audit (\S\ref{sec:honesty}): null-state and
wrong-session capsule swaps move choice accuracy by only 1--2\,pp; we
report NLL gains as the primary metric and publish the decomposition
analysis and negative results.
\item A deployed system (\S\ref{sec:live}): an OpenAI-compatible proxy
that folds conversation overflow into the capsule live and runs the
zkVM proof queue in the background.
\end{enumerate}

\section{The 22\,KB Memory State}
\label{sec:state}

\subsection{Format}
The state is exactly \statebytes{} bytes:
\[
11 \text{ heads} \times 32 \text{ keys} \times 32 \text{ values}
\times \text{int16 (Q14)} = 22{,}528 \text{ bytes}.
\]
Each head is a fast-weight associative matrix in Q14 fixed point (a
stored value $n$ means $n/2^{14}$). Eleven $32\times32$ heads give 352
independent fact slots with 32-dimensional payloads while landing on
Mina's ${\sim}22$\,KB constant-size figure. The state carries a full
SHA-256 digest; any write changes it, so tampering is detectable. Disk
exports use a versioned capsule envelope (magic, version, step, chain
head, payload hash, payload); a flipped bit fails the hash check loudly
on load.

\subsection{The fold}
A document is a 2560-d Q14 embedding $x$ (Qwen3-Embedding-4B
\cite{qwen3}). Learned integer linear layers map the full 2560-d
embedding into 11 per-head keys and values ($W_{\text{key}},
W_{\text{val}} \in \mathbb{Z}^{352 \times 2560}$ plus biases $b_{\text{key}},
b_{\text{val}}$); writing head $h$'s 32-d block as $W_{\text{key}}[h]$,
$b_{\text{key}}[h]$, $W_{\text{val}}[h]$, $b_{\text{val}}[h]$:
\begin{align}
k &= \operatorname{normalize}\!\left((W_{\text{key}}[h]\, x \gg 14) + b_{\text{key}}[h]\right)
  && \text{Q14 unit key, integer }\sqrt{\cdot}\\
v &= \operatorname{clip}_{16}\!\left((W_{\text{val}}[h]\, x \gg 14) + b_{\text{val}}[h]\right)
  && \text{bounded int16}\\
r &= (k S_h) \gg 14
  && \text{recalled value}\\
\delta &= \beta_h (v - r) \gg 14
  && \text{correction}\\
S_h &\leftarrow (\lambda_h S_h \gg 14) + (k \otimes \delta \gg 14)
  && \text{decay + rank-1 update}
\end{align}
This is the Delta rule of the fast-weight / linear-attention
family~\cite{schlag2021fast,yang2024delta}: writing a fact under the
same key replaces it rather than blending, and per-head learnable
gates $\beta$ (write strength) and $\lambda$ (forgetting) control the
update. All arithmetic is integer multiply--add--shift plus one
integer square root, which is what makes the state a cryptographic
commitment rather than a float array: the same input sequence yields
the same 256-bit digest on any machine. Fold and read cost is flat in
history size (0.45\,ms/doc fold, 0.28\,ms read on one CPU core at
100k documents) while a full-history baseline degrades linearly.

\subsection{Receipts and the light client}
\label{sec:receipts}
Every write emits a receipt and advances a rolling chain head:
\begin{align}
b_t &= H(\,t \,\|\, a_{t-1} \,\|\, H(d_t) \,\|\, H(S_t)\,)\\
a_t &= H(\,a_{t-1} \,\|\, b_t\,)
\end{align}
where $H$ is SHA-256, $d_t$ is the document, $S_t$ the new state, and
$a_t$ the accumulator. A light client holds only
$(t, a_t, H(S_t))$---three fields, forever---and verifies a claimed
state in $O(1)$. A full audit replays every document and recomputes
the accumulator: any inserted, dropped, reordered, or edited document
breaks the chain. This is the same trust split as a blockchain light
client, applied to memory.

\section{Verifiable Memory Writes (SP1 Recursive IVC)}
\label{sec:zk}
The integer fold ports to the SP1 zkVM~\cite{sp1} unchanged, because
there are no float semantics to emulate. The guest reads the quantized
writer weights (3{,}605{,}932 bytes, SHA-256 committed) and the raw
Q14 documents, runs the fold with the receipt chain, and commits
$(t, S_t, H(S_t), a_t)$ as public values.

\paragraph{Execute mode (fast integrity check).} Full zkVM guest replay
of a session's cumulative documents, checking the capsule's step, state
digest, accumulator, and weights digest: ${\sim}13$\,s for 34 documents
(99.6M cycles) on an ARM desktop GPU host; used as the background
audit in the live proxy.

\paragraph{Prove mode (succinct proof).} A compressed recursive STARK.
The base proof for 199 documents costs 238.9M cycles (${\sim}24$\,min)
and 1.24\,MiB; each further document is a recursive step verifying the
previous proof (33.8M cycles, ${\sim}5.7$\,min). Verification is
${\sim}28$\,ms with no history access.

Exactness inside the guest is nontrivial at this scale: for batches
larger than four documents the prover supplies exact int64 pre-shift
dot products and the guest checks them with a 2-round exact i128
Fiat--Shamir Freivalds protocol (u64 challenges, soundness error
$\le 2^{-128}$). Patching the \texttt{sha2} crate to SP1's hardware
SHA-256 precompile cut hashing cycles $6.8\times$. The resulting
capsule, read from the proof's verified public values, is
byte-for-byte identical to the Python fold; we verified four-way
agreement (Python $=$ native Rust $=$ zkVM execute $=$ zkVM proof) on
real unseen sessions.

\paragraph{What the proof proves, precisely:} ``this 22\,KB state was
produced by running writer weights $W$ over the document sequence
committed to accumulator $a$.'' It does \emph{not} prove the embedding
model ran honestly (embeddings are trusted inputs, or would need their
own proof), and it does not constrain the downstream decoder.

\section{Training Without a Teacher}
\label{sec:training}
The reader addresses the state with query keys, then produces $M$
memory tokens (16 slots $\times$ the decoder's hidden width) from the
recalled values plus the question embedding. Training is end-to-end
through a frozen causal LM:
\begin{center}
\small
\texttt{docs -> fold (STE Q14) -> 22KB state -> reader -> [16, H] tokens}\\
\texttt{tokens replace <|memory|> embeddings in the frozen LM -> CE(answer)}
\end{center}
Gradients flow from the LM's loss back through the token injection,
the reader, and the straight-through quantizer into the Delta-rule
writer; the LM itself never updates. The Q14 straight-through
estimator is the key trick: the trained weights survive hard int16
quantization with no accuracy cliff (float vs.\ quantized state agree
to the 7th decimal in cosine; the int16 writer matches the float
writer at 0.999991 cosine across all held-out questions). No teacher
weights, no distillation target, and no memory-module architecture
appear anywhere in training. The data format (parquet questions plus
precomputed embedding stores) is shared with the Memorilla-Data
release~\cite{memorilla2026}, which we use purely as a public
benchmark source.

\section{Evaluation}
\label{sec:eval}
All QA evaluations follow Memorilla's protocol exactly: frozen
Qwen3-8B decoder~\cite{qwen3} (bfloat16, greedy, thinking disabled),
16 \texttt{<|memory|>} slots in the system prompt, Qwen3-Embedding-4B
nearest-neighbor choice scoring. Every \method{} number is produced
from a capsule serialized to bytes and reloaded
(\texttt{to\_bytes} $\to$ \texttt{from\_bytes}), so no float state can
leak from writer to reader.

\subsection{Live system}
\label{sec:live}
The proxy runs daily in front of a local chat backend. Sessions start
with no memory; past an 80{,}000-token conversation window (system
prompt excluded, never folded), the oldest turns fold into the
capsule, memory notes are injected into the system prompt, and the
background queue replays each fold in the zkVM, checking step, state
digest, accumulator, and weights digest against the capsule and
receipt chain. Folding 34 messages / 6{,}044 tokens produces the
22{,}606-byte capsule in milliseconds; the execute check takes
${\sim}13$\,s.

\section{Honesty Audit}
\label{sec:honesty}
We report three uncomfortable measurements rather than bury them:
\begin{enumerate}
\item \textbf{Choice-accuracy deltas understate the memory signal.}
Swapping the real capsule for a zeroed state or a wrong-session
capsule changes pv4/test choice accuracy by only 1--2\,pp (64.2 real
vs.\ 62.4 zeroed vs.\ 63.4 wrong-session on a 500-row slice), even
though the NLL effect is large ($+2.16$ nats for the distilled
model). The nearest-neighbor choice scorer saturates; NLL is the
honest headline metric. Full decomposition of state-routed vs.\
question-bypassed reader energy is future work.
\item \textbf{Lossy compression is real.} 40{,}000 tokens of history
into 22\,KB is roughly 160\,KB of text into 22\,KB: gist and
preferences survive; verbatim long lists do not. \S\ref{sec:capacity}
bounds where this bites.
\item \textbf{Embedding lock-in.} Capsules are bound to one embedding
geometry and a reader checkpoint. The capsule is portable across
processes and machines, not across encoders.
\end{enumerate}
Known costs: SP1 prove is minutes per step on desktop-class hardware
(execute-mode checks are seconds); the training-data format inherits
from the Memorilla-Data release for benchmark comparability; all
evaluation used Qwen-family models.

\section{Related Work}
\textbf{Memorilla}~\cite{memorilla2026} reads latent semantic memory
tokens in $O(1)$; our training-data format and evaluation protocol
follow theirs for comparability, and their module served as the
distillation teacher in early phases. \method{} differs in $O(1)$
writes, integer bit-exactness, portability, and verifiability; as of
\S\ref{sec:eval} the self-trained capsule matches their teacher without
using it. \textbf{Agent memory systems}: MemGPT~\cite{packer2023memgpt}
manages memory tiers by paging text through a context window;
Mem0~\cite{chhikara2025mem0} maintains an external fact store via
LLM-driven CRUD operations; LongMemEval~\cite{wu2024longmemeval} and
LoCoMo~\cite{maharana2024locomo} benchmark such systems on multi-session
recall. \method{} compresses the same histories into a single
constant-size artifact with a proof, rather than storing and retrieving
growing text. \textbf{Fast weights / DeltaNet / linear
attention}~\cite{schlag2021fast,yang2024delta,hatamizadeh2026gdn2,cabannes2026sdm}:
the write rule is from this family, and recent work scales its state or
gates; \method{}'s contribution is making it fixed-point exact,
capsule-portable, receipt-chained, and zk-provable, at a deliberately
Mina-sized constant. \textbf{Compressed memory}:
MEMORY-VQ~\cite{zemlyanskiy2023memoryvq} vector-quantizes precomputed
token KV caches; \method{} instead trains a streaming associative state
whose updates are $O(1)$ and integer-exact. \textbf{Verifiable ML}:
zkDL~\cite{sun2023zkdl} proves deep-learning \emph{training}; \method{}
applies recursive IVC to neural \emph{memory state}---a much smaller,
fixed computation, which is what makes 28\,ms verification of an
unbounded history possible. \textbf{Mina / recursive SNARKs /
SP1}~\cite{mina2020,sp1}: the constant-size-verifiable-state pattern and
the IVC recursion structure. \textbf{RAG}~\cite{lewis2020rag}: complementary for
verbatim recall; \method{} targets gist, synthesis, and
constant-size trust.

\section{Limitations and Future Work}
The capacity knee is measured on gist-style QA; verbatim-recall regimes
should shift it and need their own sweep. The reader routes part of
its signal around the state (question bypass); architecturally
constraining the reader to use the state more is open. Prove-mode cost
is minutes on CPU-class hosts; folding schemes (Nova-family) and GPU
provers are the natural speedup. Capsule merging (two agents, two
capsules, one combined proof) is algebraically plausible for linear
fast-weights and unverified. Cryptographic unlearning---proving a
capsule was built without a revoked document---is the most direct
application of the receipt chain and is unbuilt.

\section{Conclusion}
A 22\,KB integer state, trained by nothing but a frozen LM's own
language-modeling loss, matches a megabyte-scale cross-attention memory
teacher on held-out personal QA; folds a real developer's coding
history into concrete, recallable facts; carries a receipt chain that
turns memory tampering into a hash mismatch; and proves its own writes
in a zkVM with 28\,ms verification. Memory for long-horizon agents can
be constant-size, portable, and honest at the same time.

\paragraph{Reproducing.} The pure-NumPy core and 67 tests run on a
laptop CPU; e2e training runs on a single 12\,GB GPU; SP1 proofs run on
Linux/ARM; the proxy runs on any host with an OpenAI backend. The
repository contains the full phase-by-phase experimental log
(\textsc{DESIGN.md}).
